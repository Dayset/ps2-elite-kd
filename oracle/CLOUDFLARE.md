# PS2MapOracle on Cloudflare + GitHub Pages (updated 2026-10-18)

The live pipeline no longer depends on an agent, a VM or a paste step.

```
Census REST ──► ps2-oracle Worker, cron every minute ──────────────────► D1 "ps2-oracle"
                 │ map + world_event (METAGAME, FACILITY)               snap metagame flip alert
                 │ JS odds engine → live states + ticks + bench          tick bench pop meta
                 │ settlement from Census final scores                   report radar
                 │ AI Commander fan-out: POST /internal/commander (SELF binding, one per live alert)
                 │
                 │  Honu bridge (Honu's Anubis check challenges Cloudflare, not GitHub Actions):
                 │  GET /honu/pending ◄── ps2-elite-kd-cache Worker 5-min cron
                 │                        (worker/src/oracle-tick.js, ORACLE service binding)
                 │                        └─ only when pending: dispatch oracle-honu.yml
                 │                           (+ backstop schedule :07 / :37)
                 │  GET /honu/queue  ◄─┐
                 │  GET /honu/radar  ◄─┤ GitHub Actions: oracle-honu.yml → oracle-worker/honu-job.mjs
                 │  POST /honu/ingest ◄┘   ├─► Honu /api/population/{world}/zones
                 │                         ├─► Honu /api/alerts/{world}/{instance}/participants
                 ▼                         └─► PS2 Radar (flagged players only)
GitHub Pages /oracle/ (dashboard) ◄── GET /live /alert /history /health
GitHub Actions: deploy-oracle.yml (deploy) · oracle-commander.yml, oracle-honu-probe.yml (manual only)
```

### Endpoints

### D1 tables

`snap` (map snapshots, pruned at 30 days) · `metagame` (METAGAME rows) · `flip` (FACILITY rows, pruned at 90 days) · `alert` (one row per alert: state, status, winner, basis, final, flags, commander) · `tick` (win-history points) · `bench` (benchmark slices + Brier) · `meta` (`last_cycle`, `last_ok`, `last_commander`, `last_honu`, `last_crash`, `cron_seen`) · `pop` (Honu population per world/zone, written by `/honu/ingest` about every 5 min) · `report` (per-alert outlier report) · `radar` (PS2 Radar cache, rechecked after 3 days).

### External sources

- **Census REST** (`census.daybreakgames.com`, service ID `daysetps2legends` or `CENSUS_SERVICE_ID`): `map`, `world_event` METAGAME and FACILITY.
- **Honu** (`wt.honu.pw/api`), called **only from the GitHub Actions Honu job**, never from the Worker (Honu's Anubis bot check challenges Cloudflare's network, its JSON API included): `GET /population/{world}/zones` (worlds with a live alert), `GET /alerts/{world}/{instance}/participants?excludeOutfits=true` (after an alert settles).
- **PS2 Radar** (`ps2radar.com`), also from the Honu job: second opinion on flagged players only.

### Tracing population and outliers from Honu to the dashboard

1. The Worker's minute cycle knows which alerts are live and which settled alerts still lack a report; `/honu/pending` says whether any such work exists.
2. Every 5 minutes the cache Worker (`oracle-tick.js`) asks `/honu/pending` and, if there is work, dispatches `oracle-honu.yml` (backstop at :07/:37).
3. The job (`honu-job.mjs`) reads `/honu/queue`, fetches Honu population per live world and participants per settled alert, builds the outlier report (`outliers.js` rules), looks up flagged players on PS2 Radar (reusing `/honu/radar` cache), then `POST /honu/ingest`.
4. Ingest writes `pop`, `report`, `radar` and `meta.last_honu`.
5. The next minute's cycle uses population ≤ 15 min old for `state.pop` / `win_popadj`; `/live` and `/alert` return the report summary and outliers; the dashboard shows them.

## What changed from the agent pipeline

- **Collection:** REST every minute from Cloudflare instead of two long-lived Python
  processes on a VM that was replaced several times a day. Alert start/end and base
  flips come from Census `world_event` (METAGAME, FACILITY), so no WebSocket is needed
  for odds or settlement. Census service ID: `daysetps2legends` (or `CENSUS_SERVICE_ID`).
- **Servers:** 1 Osprey, 10 Wainwright, 25 Briggs, 40 SolTech (19 Jaeger dropped).
- **Alert kinds:** Unstable Meltdown ids (176–179, 186–193, 248–250) are labelled
  `kind: "meltdown"`; everything else tracked is `territory`. 227 (Outfit Wars) is not
  tracked. Sudden Death (236–240) is matched to its alert by world + zone.
- **Transport:** none. The state the UI reads is the state the engine wrote — the
  paste-corruption failure class (CENSUS_ERRORS §C) is gone.
- **Settlement:** from the `ended` METAGAME row's own `faction_vs/nc/tr` (Census's
  final score), at +0/+5/+10 min. A sudden-death event (236–240) on the same
  world+zone at the alert's end decides draws on kills. Our last pre-end snapshot is
  only a cross-check and adds flags: `snapshot_winner_X`, `neutral_heavy:<owned%>`,
  `snapshot_stale`. Neutral-facility corruption can no longer change a winner.
  Checked against the old pipeline's last 8 settlements: 6 agree; 1-4-49341
  (old VS, Census TR 35.3 vs VS 32.9) and 1-6-49337 (old VS; Census ran sudden
  death 238 which TR won on kills) disagree.
- **Population:** Honu `GET /api/population/{world}/zones` for worlds with a live
  alert, fetched by the Honu job about every 5 minutes and stored in table `pop`;
  the odds use it while it is ≤ 15 minutes old. The state carries `pop`, `pop_ns` (NSO), `pop_source`
  and `win_popadj` (population-weighted odds; blend weight 1 at t0 falling to 0 at t60).
- **Live KD:** removed (Honu's `realtime-alert` returns `[]`); the state no longer carries
  `kd` / `kd_source` and the dashboard has no KD rows (#22).
- **AI Commander:** computed in the Worker (`commander.js`, exact port of
  `commander_live.py`) every minute for each live alert, in its own invocation through
  the `SELF` service binding (`/internal/commander`), stored in `alert.commander`. The
  Actions workflow is now a manual cross-check only.
- **Outliers:** after an alert settles, the Honu job reads Honu
  `GET /api/alerts/{world}/{instance}/participants` (queued every 4 min, up to 12
  attempts, within 6 h of the end). Tiers: KD ≥ 5 and KPM ≥ 2 ⚠️ early, KPM ≥ 3 ☠️
  confirmed; floor 10 minutes online and 25 kills. Burst tier (#21) for short
  sessions, no floor or KD rule: KPM ≥ 5 and ≥ 15 kills in ≥ 2 min → ☠️ burst (counted as
  confirmed). Flagged players get a PS2 Radar
  second opinion (≤ 5 per run, 2.5 s apart, 25/day, cached 3 days). Tables `report`,
  `radar`. A flag is a statistical outlier, never an accusation.
- **Benchmark:** slices t0/t30/t60 (90-min), t0/t15/t30 (45-min), t0/t10/t20 (30-min).
  t0 is only recorded when the alert is first seen within 5 minutes of its start.
  Each slice also has a population-weighted twin (`t0_pop`, `t30_pop`, …) when Honu
  population was available. `/history` returns mean Brier per slice.

## Free-plan budget (Workers Free + D1 Free)

- 1,440 cron runs/day; each run ≈ 4 map calls + 2 world_event calls to Census. The
  Worker makes no Honu or PS2 Radar calls.
- **Fan-out invocations count as requests** (Workers Free: 100k/day): one
  `/internal/commander` call per live alert per minute. With 3 live alerts that is
  ≈ 3 × 1,440 ≈ 4.3k requests/day, plus dashboard reads and the cache Worker's
  `/honu/pending` check (288/day, through a service binding).
- **GitHub Actions minutes** for `oracle-honu.yml`: free (public repo). It runs only
  when there is work, plus the :07/:37 backstop.
- D1 queries per run stay well under 50 (bulk `json_each` inserts; tested).
- D1 writes ≈ 30k rows/day (limit 100k) plus one `pop` row per live zone per Honu run (~5 min);
  storage ≈ 30 MB/day of snapshots, pruned daily at 04:07 UTC: snapshots at 30 days,
  flips at 90 (`tick`, `bench`, `pop`, `report`, `radar` are not pruned yet).
- CPU: each run parses only the ~20 KB tree bin it needs.

## Not migrated yet

- **BonusCheques and replays** still live only in the Muse artifact (`hex-betting-game`).
  Accounts (`/auth/*`) and virtual-points betting (`/bet/*`) now run in the Worker.
- **No live per-player data:** per-player outliers need a Census kill stream, and an
  always-on stream does not fit the free plan, so outliers arrive only after an alert
  ends (Honu job). Population is refreshed about every 5 minutes, not every minute.
- **Cut tracker** (`cut_tracker_run.py`) still runs only on the old VM.

## Operations

- Health: `GET /health` (`ok`, ages of the last cycle and last fully successful cycle,
  the last cycle report with per-world map status and errors, `last_commander`,
  `last_honu`).
- Honu bridge: check `last_honu` in `/health`, the `oracle-honu.yml` run log in Actions,
  or run `oracle-honu-probe.yml` if Honu seems to block Actions too.
- Debug: `GET /cycle` runs a cycle now (rate-limited to one per 50 s) including the
  commander fan-out; `GET /crash` shows the last crash and the last cron breadcrumb.
- Query data directly: Cloudflare D1 console or the Cloudflare connector
  (`SELECT key, status, winner, flags FROM alert ORDER BY start_ts DESC LIMIT 20`).
- Model update: change JSON in `oracle/backend`, run `node oracle-worker/build-trees.mjs`,
  regenerate the parity fixture (`python3 oracle-worker/make-parity-fixture.py`), push.
