# PS2MapOracle on Cloudflare + GitHub Pages (updated 2026-10-18)

The live pipeline no longer depends on an agent, a VM or a paste step.

```
Census REST ─────┐  map + world_event (METAGAME, FACILITY)
Honu population ─┤  /api/population/{world}/zones (live-alert worlds)
Honu realtime ───┤  /api/realtime-alert (live KD, when Honu has the alert)
                 ▼
        ps2-oracle Worker, cron every minute ──────────────► D1 "ps2-oracle"
          │ JS odds engine → live states + ticks + bench       snap metagame flip alert
          │ settlement from Census final scores                tick bench pop meta
          │ fan-out through the SELF service binding:          report radar
          │   POST /internal/commander  (one per live alert)
          │   POST /internal/report     (settled alerts) ──► Honu /api/alerts/{world}/{instance}/participants
          │                                                ──► PS2 Radar (ps2radar.com), flagged players only
          ▼
GitHub Pages /oracle/ (dashboard) ◄── GET /live /alert /history /health
GitHub Actions: deploy-oracle.yml (deploy) · oracle-commander.yml and oracle-honu-probe.yml (manual only)
```

| Piece | Where | Notes |
|---|---|---|

| Outliers | `oracle-worker/src/outliers.js` + `radar.mjs` (repo root) | Post-alert report from Honu participants, PS2 Radar second opinion; tables `report`, `radar` |

### Endpoints

| Endpoint | Auth | What |
|---|---|---|
| `GET /health` (also `/`) | none | `ok`, age of last cycle / last fully successful cycle, `last_cycle` report, `last_commander` |
| `GET /live` | none | Live, settling and sudden-death alerts plus recently ended ones (state, commander, report summary) |
| `GET /alert?key=` | none | Any alert (live or settled): `alert`, `ticks`, `bench` (slices + Brier), `outliers` |
| `GET /history?days=` | none | Settled/canceled/unresolved alerts (1–30 days, default 7) and mean Brier per duration and slice |
| `GET /cycle` | none | Manual debug cycle, refused (429) if a cycle ran in the last 50 s; also runs the commander and report fan-outs |
| `GET /crash` | none | `last_crash` and `cron_seen` breadcrumbs |
| `GET /export?world=&zone=&since=` | `X-Oracle-Key` | Snapshots, METAGAME rows and flips for the Python cross-check |
| `POST /commander` | `X-Oracle-Key` | Store an externally computed commander for a live alert |
| `POST /internal/commander` | `X-Oracle-Key` | Fan-out target: compute the commander for one live alert |
| `POST /internal/report` | `X-Oracle-Key` | Fan-out target: outlier report for one settled alert |

### D1 tables

`snap` (map snapshots, pruned at 30 days) · `metagame` (METAGAME rows) · `flip` (FACILITY rows, pruned at 90 days) · `alert` (one row per alert: state, status, winner, basis, final, flags, commander) · `tick` (win-history points) · `bench` (benchmark slices + Brier) · `meta` (`last_cycle`, `last_ok`, `last_commander`, `last_report`, `last_crash`, `cron_seen`) · `pop` (Honu population per world/zone/minute) · `report` (per-alert outlier report) · `radar` (PS2 Radar cache, rechecked after 3 days).

### External sources

- **Census REST** (`census.daybreakgames.com`, service ID `daysetps2legends` or `CENSUS_SERVICE_ID`): `map`, `world_event` METAGAME and FACILITY.
- **Honu** (`wt.honu.pw/api`): `GET /population/{world}/zones` (only worlds with a live alert), `GET /realtime-alert` (live KD), `GET /alerts/{world}/{instance}/participants?excludeOutfits=true` (after an alert settles).
- **PS2 Radar** (`ps2radar.com`): second opinion on flagged players only.

## What changed from the agent pipeline

- **Collection:** REST every minute from Cloudflare instead of two long-lived Python
  processes on a VM that was replaced several times a day. Alert start/end and base
  flips come from Census `world_event` (METAGAME, FACILITY), so no WebSocket is needed
  for odds or settlement. Census service ID: `daysetps2legends` (or `CENSUS_SERVICE_ID`).
- **Servers:** 1 Osprey, 10 Wainwright, 25 Briggs, 40 SolTech (19 Jaeger dropped).
- **Alert kinds:** Unstable Meltdown ids (176–179, 186–193, 248–250) are labelled
  `kind: "meltdown"`; everything else tracked is `territory`. 227 (Outfit Wars) is not
  tracked. Sudden Death (236–240) is matched to its alert by world + zone.
- **Transport:** none. The state the UI reads is the state the engine wrote — the
  paste-corruption failure class (CENSUS_ERRORS §C) is gone.
- **Settlement:** from the `ended` METAGAME row's own `faction_vs/nc/tr` (Census's
  final score), at +0/+5/+10 min. A sudden-death event (236–240) on the same
  world+zone at the alert's end decides draws on kills. Our last pre-end snapshot is
  only a cross-check and adds flags: `snapshot_winner_X`, `neutral_heavy:<owned%>`,
  `snapshot_stale`. Neutral-facility corruption can no longer change a winner.
  Checked against the old pipeline's last 8 settlements: 6 agree; 1-4-49341
  (old VS, Census TR 35.3 vs VS 32.9) and 1-6-49337 (old VS; Census ran sudden
  death 238 which TR won on kills) disagree.
- **Population:** Honu `GET /api/population/{world}/zones` for worlds with a live
  alert, stored in table `pop`. The state carries `pop`, `pop_ns` (NSO), `pop_source`
  and `win_popadj` (population-weighted odds; blend weight 1 at t0 falling to 0 at t60).
- **Live KD:** Honu `GET /api/realtime-alert` when Honu has the alert
  (`state.kd_source = "honu"`); otherwise KD stays the neutral 1.0 default and the UI
  hides it.
- **AI Commander:** computed in the Worker (`commander.js`, exact port of
  `commander_live.py`) every minute for each live alert, in its own invocation through
  the `SELF` service binding (`/internal/commander`), stored in `alert.commander`. The
  Actions workflow is now a manual cross-check only.
- **Outliers:** after an alert settles, a report job (`/internal/report`, up to 3 alerts
  per minute, retried up to 12 times) reads Honu
  `GET /api/alerts/{world}/{instance}/participants`. Tiers: KD ≥ 5 and KPM ≥ 2 ⚠️ early,
  KPM ≥ 3 ☠️ confirmed; floor 10 minutes online and 25 kills. Flagged players get a PS2
  Radar second opinion (max 5 per alert, 2.5 s apart, cached 3 days). Tables `report`,
  `radar`. A flag is a statistical outlier, never an accusation.
- **Benchmark:** slices t0/t30/t60 (90-min), t0/t15/t30 (45-min), t0/t10/t20 (30-min).
  t0 is only recorded when the alert is first seen within 5 minutes of its start.
  Each slice also has a population-weighted twin (`t0_pop`, `t30_pop`, …) when Honu
  population was available. `/history` returns mean Brier per slice.

## Free-plan budget (Workers Free + D1 Free)

- 1,440 cron runs/day; each run ≈ 4 map calls + 2 world_event calls to Census, plus
  Honu population (one call per world with a live alert) and at most one
  `realtime-alert` call.
- **Fan-out invocations count as requests** (Workers Free: 100k/day): every minute, one
  `/internal/commander` call per live alert and one `/internal/report` call per settled
  alert still waiting for its report (max 3). With 3 live alerts that is ≈ 4 × 1,440 ≈
  6k requests/day, plus dashboard reads.
- D1 queries per run stay well under 50 (bulk `json_each` inserts; tested).
- D1 writes ≈ 30k rows/day (limit 100k) plus one `pop` row per live zone per minute;
  storage ≈ 30 MB/day of snapshots, pruned daily at 04:07 UTC: snapshots at 30 days,
  flips at 90 (`tick`, `bench`, `pop`, `report`, `radar` are not pruned yet).
- CPU: each run parses only the ~20 KB tree bin it needs.

## Not migrated yet

- **Betting, accounts, auth, BonusCheques, replays** still live in the Muse artifact
  (`hex-betting-game`) and still need the old `hex-betting-live-push` job. Auth can use
  an on-demand Durable Object that only connects to the Census stream while a
  login challenge is pending (fits the free plan; an always-on stream does not,
  because the cache Worker's kill monitor already uses most of it).
- **Live per-player outliers** (during an alert) need a Census kill stream, and an
  always-on stream does not fit the free plan. Outliers are reported after the alert
  ends instead (see Outliers above); live KD comes from Honu when available.
- **Cut tracker** (`cut_tracker_run.py`) still runs only on the old VM.

## Operations

- Health: `GET /health` (`ok`, ages of the last cycle and last fully successful cycle,
  the last cycle report with per-world map/Honu status and errors, `last_commander`).
- Debug: `GET /cycle` runs a cycle now (rate-limited to one per 50 s) including the
  fan-outs; `GET /crash` shows the last crash and the last cron breadcrumb.
- Query data directly: Cloudflare D1 console or the Cloudflare connector
  (`SELECT key, status, winner, flags FROM alert ORDER BY start_ts DESC LIMIT 20`).
- Model update: change JSON in `oracle/backend`, run `node oracle-worker/build-trees.mjs`,
  regenerate the parity fixture (`python3 oracle-worker/make-parity-fixture.py`), push.
